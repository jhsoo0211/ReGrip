# ReGrip 구현 검증 기록

기준일: 2026-09-05. 기준 커밋 `ee4d6e0b` 이후 실센서 연결·초보자 게임 개선 작업. 사용자 최종 결정에 따라 기존 본편 디자인을 유지한다. `design-review/`의 세 가지 HTML은 참고용이며 제품 테마로 적용하지 않았다.

## 실행한 검사

SQLite 백업은 로컬 `backend/.backups/regrip_dev.db.pre-004.20260905T123028898409Z.bak`에 있으며 Git에 포함하지 않는다. 업그레이드 과정에서 기존 세션·XP를 삭제하거나 재계산하지 않았다.

## 회귀 검사가 다루는 경계

- BLE CSV 형식·최대 길이·범위·중복·uint32 순환, 예전 연결 이벤트, 실패 후 재시도, 장치 선택 사용자 동작, 저장 장치 복원.
- 80ms 필터, FSR 제어와 가변저항 진단 분리, 500ms stale, 증가/감소 ADC 보정, 부족·불안정 샘플, 계정·장치 변경과 재보정.
- 준비 상태 제한, 끊김 중 무득점·수동 재개, 버튼 해제·포인터 취소·탭 숨김, 모든 게임의 연습 무저장 및 같은 페이지 재시작.
- 낮은 FPS의 실제 유지·유예·이동 시간, 250ms 초과 프레임 지연 시 일시정지, 리듬 일시정지 전 유효 쥐기 보존, 크레인 운반 중 종료 미성공 처리.
- 세션 출처/시작 시 보정 스냅샷, 센서 통계와 전체 보상 분리, 한국시간 자정, 오프라인 최초 제출 중 조회·재전송 중 새 기록 보존.
- 계정·API별 기록/아웃박스/보정/설정 캐시 분리, 기존 소유자 미상 데이터 보존, 늦은 응답·401·refresh 격리, 게임 도중 계정 변경 시 저장 차단.
- 실제 sensor-service→sensor-ui→shared 순서로 파일을 평가한 초기화 검사와 같은 문서의 계정·API 변경 후 새로고침 제한.
- Wi-Fi `forceRaw` 보정·% 표시, 캡처 중 초기화, 연결 변경 시 이전 기준 폐기, 뒤로 가기 캐시 복귀 시 전체 초기화.
- 잘못된 API 입력 422, 극단 날짜 UTC 변환, 정적 연구 경로 차단, 기존 SQLite 값 보존·백업 WAL 반영·멱등 업그레이드·실패 롤백.

## 남은 실기기 확인

Windows Chrome와 Edge에서 각각 다음을 확인해야 한다. 자동 검사를 실제 기기 확인으로 간주하지 않는다.

1. BLE 펌웨어를 ESP32에 올리고 GPIO34 압력·GPIO35 가변저항이 기대한 방향과 범위로 변하는지 확인한다.
2. localhost에서 장치 연결 → 이완 1초 → 편안한 쥐기 1초 → 연습 → 본게임 → 출처가 표시된 기록 순서로 진행한다.
3. 전원 재인가·500ms 이상 전송 중단·재시도 소진 뒤 수동 재연결·페이지 이동·뒤로 가기를 확인한다.
4. 압력을 유지한 채 일시정지 후 손을 펴고 재개한다. 시간·판정이 멈춘 구간에 누적되지 않는지 확인한다.
5. 초보자에게 풍선 3초 유지와 크레인 단계별 조작이 가능한지, 필터 80ms와 BLE 20Hz 조합의 반응이 적절한지 관찰한다.

PostgreSQL의 001→수정된 002→003→004 실행과 Windows 실제 화면 검증은 별도다. XIAO 새 회로·모터·EMG 제품 연결은 이번 구현에 포함되지 않는다. 서버는 정규화된 요약으로 보상을 재계산하지만 실제 센서 사용과 게임 진행의 진위를 증명하지 않는다.
