- 세션 출처/시작 시 보정 스냅샷, 센서 통계와 전체 보상 분리, 한국시간 자정, 오프라인 최초 제출 중 조회·재전송 중 새 기록 보존.

## 펌웨어 입력 경로 추가 확인

2026-09-05, `182a481d` 이후 후속 작업에서 USB 시리얼을 기존 측정 로그와 같은 4열로 맞췄다. BLE 3열·50Hz 측정·20Hz 전송은 유지했다. `scripts/flash-sensor.ps1`은 포트 명시, 없는 포트·Bluetooth 가상 포트 거부, 빌드 전용 실행을 지원한다. 당시 확인된 COM3·COM4는 `BTHENUM` 가상 포트로, ESP32 업로드 대상으로 사용하지 않았다.

### 제공된 측정 로그 재생

`node scripts/replay-sensor.cjs --file <CSV> --rest 4095 --grip 300 --game all`로 세 파일의 각 재시작 구간을 독립 시나리오로 실행했다. **4095/300은 재현용 가정이며 사용자 보정값으로 저장하지 않았다.** 파서가 인정한 원본 측정은 총 8,245행이고, 각 연속 구간의 장치 간격은 20ms였다. 모두 유효 범위이며 잘못된 행과 중복 행은 없었다.

| 로그 | 유효 행 | 구간 | 20Hz 재생 결과 |
|---|---:|---:|---|
| idle | 4,904 | 2 | FSR 4095 고정 → 힘 0%, 네 게임 득점 0 |
| flex_steps | 1,580 | 2 | 가변저항이 변해도 힘 최대 0.94%, 네 게임 득점 0. FSR 한 표본의 작은 변동만 반영 |
| fsr_steps | 1,761 | 2 | 후반 34.72초 구간에서 힘 0–100%, 크레인 1·리듬 2·잠수함 1 성공 |

풍선은 압력 단계 로그에서 0점이었다. 게임 목표에 맞춘 손 조작 녹화가 아니므로 점수로 난이도나 실제 사용자의 완료 가능성을 판단하지 않는다. 별도 합성 raw 입력 시나리오에서는 네 게임의 목표 달성을 확인했다. CLI는 게임 종료나 수동 재개가 필요한 중단 시점까지만 진행하며 남은 로그 길이를 보고한다. 개인 원본 CSV와 로컬 `output/sensor-replay-*.json`은 Git에 포함하지 않았다.

### Chrome 화면과 실제 페이지 코드

localhost의 격리된 Chrome 검사 프로필에서 **GATT 장치·알림만 테스트 신호로 대체**했다. 앱의 SensorService, 보정 화면, 실제 DOM/SVG 게임 화면과 애니메이션은 그대로 실행했다. 사용자 브라우저의 기록과 분리된 프로필이며 연습만 실행했다.

- 연결 버튼 → 이완 4095/쥐기 300 각각 1초 보정 → 페이지 이동 후 같은 장치 기준 복원 확인.
- raw FSR만 조절해 풍선 1팝, 크레인 파지·운반·의도적 해제 1회, 리듬 4회, 잠수함 3게이트 연습 성공.
- 각 연습 종료 후 세션·아웃박스 키 없음. 센서 모드에서 헤더의 조작 안내가 “센서를 쥐어 조작”으로 표시됨.
- 잠수함 재연습 중 알림을 중단하자 약 500ms 후 stale·일시정지로 전환. 이후 700ms 동안 시간·점수 불변, 알림을 다시 보낸 뒤에도 일시정지를 유지함.
- 자동화 탭을 뒤에 두었을 때 약 1초 프레임 간격으로 정지했고, 전면으로 가져온 뒤 약 12ms 프레임 간격 및 수동 재개를 확인. 지연 검사를 우회하거나 게임 기준을 완화하지 않음.

이 검사는 실제 ESP32 무선 수신이나 Windows Edge 결과가 아니다. 전체 13페이지의 반응형·터치·접근성 검수도 포함하지 않는다.

## 남은 실기기 확인

Windows Chrome와 Edge에서 각각 다음을 확인해야 한다. 자동 검사를 실제 기기 확인으로 간주하지 않는다.

1. BLE 펌웨어를 ESP32에 올리고 GPIO34 압력·GPIO35 가변저항이 기대한 방향과 범위로 변하는지 확인한다.
2. localhost에서 장치 연결 → 이완 1초 → 편안한 쥐기 1초 → 연습 → 본게임 → 출처가 표시된 기록 순서로 진행한다.
3. 전원 재인가·500ms 이상 전송 중단·재시도 소진 뒤 수동 재연결·페이지 이동·뒤로 가기를 확인한다.
4. 압력을 유지한 채 일시정지 후 손을 펴고 재개한다. 시간·판정이 멈춘 구간에 누적되지 않는지 확인한다.
5. 초보자에게 풍선 3초 유지와 크레인 단계별 조작이 가능한지, 필터 80ms와 BLE 20Hz 조합의 반응이 적절한지 관찰한다.

PostgreSQL의 001→수정된 002→003→004 실행과 Windows 실기기 BLE·Edge 검증은 별도다. XIAO 새 회로·모터·EMG 제품 연결은 이번 구현에 포함되지 않는다. 서버는 정규화된 요약으로 보상을 재계산하지만 실제 센서 사용과 게임 진행의 진위를 증명하지 않는다.
