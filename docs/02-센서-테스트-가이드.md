# 센서 실기기 테스트 가이드 (2026-08-01)

> 대상: 팀원 BLE 펌웨어(ReGrip-Sensor, flex+FSR 2채널)와 저장소 WiFi 펌웨어의 실기기 검증.
> 도구: `tools/ble-sensor-test.html` (독립 수신 시험 페이지 — 앱 본편 무관, 어느 브랜치에서도 동작).

---

## 0. 준비물

| 항목 | 조건 |
|---|---|
| ESP32 | 팀원 BLE 스케치 업로드 상태 (시리얼 배너 `# ReGrip BLE sensor ready` 확인) |
| PC | **Chrome 또는 Edge** (Safari·Firefox는 Web Bluetooth 미지원), 블루투스 4.0+ 어댑터 |
| 서빙 | 저장소 루트에서 `npx serve .` 또는 `python -m http.server 3000` — **file:// 로 열면 안 됨** (Web Bluetooth는 localhost/HTTPS 필수) |
| 거리 | 최초 시험은 **ESP32와 2~3m 이내, 장애물·몸 가림 없이** |

접속: `http://localhost:3000/tools/ble-sensor-test.html`

## A. 기본 수신 시험 (5분)

1. ESP32 전원 인가 → 시리얼 모니터(115200)에 `# BLE connected` 전이면 광고 중.
2. 페이지에서 **[센서 연결]** → 목록에서 `ReGrip-Sensor` 선택 (최초 1회만 — 이후엔 자동).
3. **합격 기준**:
   - 수신 배지 **18~20Hz** 유지 (초록)
   - FLEX/FSR raw가 센서 조작(포텐셔미터 돌리기 / 압력 누르기)에 **즉시 반응**
   - 5분 방치 시 **"간격 이상" 증가율 ≒ 0**, "끊김 횟수" 0 (2m 이내 기준)
   - 파형 차트에 두 채널이 끊김 없이 그려짐
4. 실패 시 → §E 트러블슈팅.

## B. 캘리브레이션·게임 입력 상당값 시험

1. 손(센서) 완전 이완 상태에서 **[0% 기준 잡기]** — 최근 20샘플 평균이 저장됨.
2. 최대로 쥔 상태에서 **[100% 기준 잡기]**.
3. **합격 기준**: 이완↔최대를 오갈 때 큰 % 표시가 **0↔100 부근을 왕복**하고 중간 세기에서 중간값이 나옴. 이 값이 게임(`SensorService.onForceUpdate`)이 받게 될 입력과 동등하다.
4. 기준값은 localStorage에 저장되므로 **페이지를 껐다 켜도, 기기를 다시 만나도 즉시 적용**된다.

## C. 자동 재연결·거리 시험 (사용자 보고 이슈 재현)

1. 연결된 상태에서 ESP32를 들고 **천천히 멀어진다** → 어느 지점에서 "연결 끊김"+끊김 횟수 증가.
2. 다시 2~3m 이내로 복귀 → **3초 간격 자동 재연결**로 수신이 재개되는지 확인 (선택창 없이).
3. ESP32 **전원을 껐다 켠다** → 재광고 후 자동 연결 확인.
4. 페이지를 닫았다 다시 연다 → "저장된 기기: ReGrip-Sensor — 광고 감지 대기 중" 표시 후 자동 연결 확인.
5. **RSSI 읽는 법** (연결 전 광고 감지 중 표시): −70dBm 이상 양호 / −70~−85 불안정(끊김 잦음) / −85 이하 연결 곤란. 실사용 목표 거리에서 −70 이상 나오는지 기록해 둘 것.

> 거리 개선 팁 (펌웨어): `setupBle()`에 `BLEDevice::setPower(ESP_PWR_LVL_P9);` 한 줄 추가 시 송신 출력 +3→+9dBm.
> PC 쪽은 USB 블루투스 동글 위치(본체 뒤→앞 포트)만 바꿔도 크게 달라진다.

## D. 데이터 캡처 (ML·분석용)

1. **[기록 시작]** → 원하는 동작 수행 → **[기록 중지]** → **[CSV 다운로드]**.
2. 열 형식: `recv_iso,timestamp_ms,flex_raw,fsr_raw`. `timestamp_ms`는 ESP32 `millis()`(부팅 기준)이므로 절대 시각은 `recv_iso` 사용.
3. **주의**: BLE 경로는 50Hz 측정 → 20Hz 전송이라 중간 샘플이 버려진다. **고밀도(50Hz) 수집이 필요하면 팀원 시리얼 CSV 스케치**(USB, `sample_id,timestamp_ms,flex_raw,fsr_raw`)로 받고, PlatformIO 모니터 출력을 파일로 저장하는 편이 맞다.

## E. 트러블슈팅

| 증상 | 원인·조치 |
|---|---|
| 선택 목록에 안 뜸 | ①거리(2~3m 이내로) ②ESP32 전원·광고 여부(시리얼 배너) ③**다른 앱(nRF Connect·휴대폰)이 이미 연결 중** — BLE는 1:1이라 기존 연결 끊어야 광고 재개 ④PC 블루투스 켜짐 확인 |
| 연결 직후 끊김 반복 | 거리·장애물(몸·벽) 제거, RSSI 확인, TX power 상향(§C 팁), 2.4GHz 혼잡 환경(공유기 밀집)이면 장소 변경 |
| "보안 컨텍스트 아님" 경고 | file:// 로 열었음 → localhost 서버로 열기 |
| 연결 버튼 비활성 | Safari/Firefox → Chrome/Edge로 |
| 값이 고정/이상 | 배선 확인(GPIO35 포텐셔미터·GPIO34 압력), 두 값이 서로 물들면 펌웨어에 `readAdcStable`(첫 측정 버리기) 적용 |
| 자동 재연결이 안 됨 | 구형 Chrome은 `getDevices` 미지원 — 페이지 안내에 따라 [센서 연결]로 1회 재선택 |

## F. (참고) 저장소 WiFi WebSocket 펌웨어 시험 — `firmware/esp32-grip-sensor`

팀원 BLE 스케치와 별개로, 저장소 펌웨어(ADR-04-0 채택 경로)는 아직 실기 검증 전(pre-hardware)이다:

1. `include/config.h.example` → `config.h` 복사, WiFi SSID/PASS 입력 → PlatformIO 업로드.
2. 시리얼에서 IP 확인 (공유기 실패 시 SoftAP `ReGrip-Sensor`/`regrip1234` → `192.168.4.1`).
3. 현재 앱에는 연결 UI가 없으므로(P0 갭) 브라우저 콘솔에서: `SensorService.connect('ws://<ip>:8080')` → 게임·캘리브레이션 화면이 실센서로 동작하는지 확인.
4. 완료 기준은 펌웨어 README의 실기 체크리스트 13항목.

## G. 판정 요약

| 시험 | 합격 기준 |
|---|---|
| 수신율 | 18~20Hz 지속, 간격 이상 증가율 ≈ 0 (2m) |
| 반응성 | 조작→화면 반영 체감 지연 없음 (<100ms) |
| 정규화 | 캘리브레이션 후 % 가 0↔100 왕복 |
| 재연결 | 범위 복귀·전원 재인가·페이지 재방문 3케이스 모두 무선택 자동 재개 |
| 안정성 | 목표 사용 거리에서 RSSI ≥ −70dBm, 5분 무끊김 |
