# 센서 연결·보정 가이드

**대상: Windows Chrome/Edge + ESP32 BLE, 2026-09-05 코드 기준.** 게임은 FSR 압력으로 조작합니다. GPIO35의 가변저항은 flex 센서를 모사한 진단 입력이며 게임을 움직이지 않습니다.

백엔드 없이도 BLE 연결·보정·게임·로컬 기록을 사용할 수 있습니다. 계정 로그인과 서버 동기화가 필요할 때 백엔드를 함께 실행합니다. 기존 제품 디자인은 유지하며 `design-review/`는 실제 센서에 연결하지 않는 별도 목업입니다.

## 1. 펌웨어와 입력 확인

현재 BLE 펌웨어는 [`firmware/esp32-ble-sensor`](../firmware/esp32-ble-sensor)입니다. 기존 `esp32-grip-sensor`는 Wi-Fi WebSocket용입니다.

| 항목 | BLE 펌웨어 계약 |
|---|---|
| 보드 | PlatformIO `esp32dev`, Arduino, `espressif32@7.0.1` |
| FSR 입력 | GPIO34, 게임 조작용 |
| 가변저항 입력 | GPIO35, flex 모사·진단용 |
| ADC | 12비트, 0~4095; 채널 전환 후 첫 읽기 폐기 |
| 측정 주기 | 채널별 50Hz, 20ms 간격 |
| BLE 전송 | 최신 표본 20Hz, 50ms 간격 |
| 시리얼 | 115200bps; CSV 50Hz와 상태 메시지 |
| 장치 이름 | `ReGrip-Sensor` |
| Service UUID | `6E400001-B5A3-F393-E0A9-E50E24DCCA9E` |
| TX characteristic | `6E400003-B5A3-F393-E0A9-E50E24DCCA9E`, READ + NOTIFY |
| 패킷 | ASCII `timestamp_ms,flex_raw,fsr_raw` |

예시는 `12340,2010,970`입니다. BLE 패킷에는 개행·NUL을 붙이지 않으며, 최대 문자열 `4294967295,4095,4095`는 20바이트여서 기본 ATT MTU 23에 맞습니다. 타임스탬프는 보드의 `millis()`이며 날짜·UTC 시각이 아닙니다.

PlatformIO가 설치된 환경에서 저장소 루트 기준으로 빌드합니다.

```powershell
pio run -d firmware/esp32-ble-sensor
```

이번 작업에서 사용한 격리 설치 환경도 저장소의 `.tools/pio`에 남아 있습니다. 이 환경으로 다시 빌드하려면 저장소 루트에서 실행합니다.

```powershell
.\.tools\pio\Scripts\python.exe -m platformio run -d firmware/esp32-ble-sensor
```

새 체크아웃에서는 선택적으로 `backend/venv/Scripts/python.exe -m venv .tools/pio` 후 `.tools/pio/Scripts/python.exe -m pip install platformio==6.1.19`로 같은 CLI 환경을 준비할 수 있습니다. `.tools/`와 빌드 산출물은 Git에 포함하지 않습니다.

이 명령은 컴파일만 합니다. 실제 보드에 업로드할 때는 Windows 장치 관리자 또는 `pio device list`로 보드의 포트를 확인한 후, 다음 예시의 `COM5`를 실제 포트로 바꿉니다.

```powershell
pio device list
pio run -d firmware/esp32-ble-sensor -t upload --upload-port COM5
pio device monitor -d firmware/esp32-ble-sensor --port COM5 --baud 115200
```

시리얼 모니터에서 가변저항을 움직일 때 두 번째 값, FSR에 힘을 줄 때 세 번째 값이 바뀌는지 확인합니다. 시리얼 모니터는 펌웨어 점검 도구입니다. 웹 앱은 시리얼 포트 대신 BLE notify를 구독합니다.

2026-09-05 빌드는 성공했고 RAM 12.0%, Flash 86.4%를 사용했습니다. 이 작업에서는 보드에 업로드하지 않았으며, 실제 전압·배선·센서 응답이나 BLE 연결은 검증하지 않았습니다. 최종 증거는 [VERIFICATION.md](VERIFICATION.md)에 있습니다.

## 2. 웹 앱에서 연결

1. 저장소 루트에서 `py -3.11 -m http.server 3000 --bind 127.0.0.1`을 실행합니다.
2. Windows Chrome 또는 Edge로 <http://localhost:3000>을 엽니다. Web Bluetooth에는 HTTPS 또는 localhost가 필요합니다.
3. 설정 또는 게임 준비 화면에서 **센서 연결**을 누릅니다.
4. 브라우저 장치 선택창에서 `ReGrip-Sensor`를 선택합니다.
5. **센서 입력 확인**을 열어 파란 압력값과 보라색 가변저항 값이 새로 들어오는지 확인합니다.
6. **센서 보정**으로 이동합니다. 연결만으로 BLE 게임 준비가 끝나지는 않습니다.

처음 연결은 버튼을 눌러 장치를 선택해야 합니다. 이미 권한을 준 장치의 연결 복원은 저장된 정확한 기기 ID에만 시도합니다. 브라우저가 기존 장치 목록을 제공하지 않거나 권한이 사라졌으면 연결 버튼으로 다시 선택합니다.

센서 없이 체험하려면 **시뮬레이션 사용**을 선택합니다. 새 브라우저의 기본 시뮬레이션 상태도 실제 센서 측정으로 표시하지 않습니다. 센서 연결이 끊겼다고 시뮬레이션으로 자동 전환하지는 않습니다.

## 3. 내 손에 맞게 보정

1. FSR을 잡는 위치를 정하고 손에 힘을 뺍니다.
2. **이완 상태 1초 기록**을 눌러 자세를 1초 유지합니다. 이것이 0% 기준입니다.
3. 같은 위치에서 편안하게 쥡니다.
4. **편안한 쥐기 1초 기록**을 눌러 자세를 1초 유지합니다. 이것이 100% 기준입니다.
5. 저장 성공 표시와 준비 상태를 확인한 뒤 게임으로 이동합니다.

각 버튼은 누른 뒤 새로 받은 1초의 FSR 값으로 중앙값을 구합니다. 각 단계 15개 이상, 수신 간격 150ms 이하가 필요합니다. 두 중앙값 차이의 절댓값이 64 ADC 미만이거나 각 단계의 흔들림(P95-P5)이 그 차이의 20%를 넘으면 다시 측정합니다.

힘을 줄수록 ADC가 증가하는 회로와 감소하는 회로를 모두 지원합니다. 화면의 0~100%는 이 두 기준 사이의 상대 압력입니다. 예를 들어 이완 700, 쥐기 2100이면 1400은 필터 적용 전 50%입니다. 반대로 이완 2100, 쥐기 700이어도 같은 방식으로 50%가 됩니다.

보정은 현재 브라우저의 API 주소·사용자·BLE 기기별로 저장합니다. 로그인 사용자·서버·장치를 바꾸면 해당 조합의 보정이 필요합니다. 같은 문서 안에서 계정이나 서버가 바뀌었다는 안내가 나오면 페이지를 새로고침합니다. 이전 논리값 보정을 BLE 원시 ADC 보정으로 대신 사용하지 않습니다. 브라우저 저장소에 저장하지 못하면 완료 처리하지 않습니다.

보정 중 센서가 끊기거나 입력 장치·사용자가 바뀌면 처음부터 다시 측정합니다. 시뮬레이션 값으로 실제 센서 보정을 저장하지 않습니다.

## 4. 연습과 본편

난이도를 저장한 적이 없으면 쉬움으로 시작합니다. 준비 화면의 연습은 최대 20초이며 게임별 목표에 도달하면 먼저 끝납니다.

| 게임 | 연습 목표 | 조작 요령 |
|---|---|---|
| 풍선 | 풍선 1개 | 힘을 줘 목표 높이로 올리고 표시된 압력 범위 안에서 3초 유지 |
| 크레인 | 놓기 1회 | 잡기 기준까지 쥔 뒤 이동 중 힘을 유지하고, 도착하면 충분히 힘을 풀기 |
| 리듬 | 박자 판정 4회 | 박자에 맞춰 쥐고, 다음 박자 전에 힘을 풀기 |
| 잠수함 | 관문 판정 3회 | 압력을 조절해 잠수함을 관문 높이에 맞추기 |

연습은 세션·XP를 저장하지 않습니다. 연습 반복이나 본편 시작 시 점수·시간·입력 상태를 새로 시작합니다. 본편은 시작 시 입력 출처와 BLE 보정 스냅샷을 고정하므로, 진행 중 입력 모드·보정을 바꾸려면 새로 시작해야 합니다.

기본 목표 압력 80%일 때 크레인 쉬움의 잡기 기준은 60%, 유지 최소 50%, 운반 최소 38%, 놓기는 30% 미만입니다. 프로필의 목표 압력을 바꾸면 이 기준도 달라집니다. 운반 중 시간이 끝난 것만으로 성공하지는 않습니다.

풍선 쉬움의 압력 유지 범위는 46~74%입니다. 풍선이 목표 높이에 들어온 상태에서 이 범위로 조절하면 멈춰서 유지 시간을 쌓습니다. 잠수함의 화면 위치와 관문 판정은 같은 필터된 압력값을 사용합니다.

## 5. 멈춤과 재연결

- **센서 입력 중단:** 마지막 유효 패킷으로부터 500ms가 지나면 센서 응답 없음 상태가 되고 게임을 멈춥니다. 형식이 잘못됐거나 중복인 패킷은 최신 수신으로 인정하지 않습니다.
- **자동 재연결:** 연결이 끊기면 1·2·4·8초 간격으로 최대 4회 시도합니다. 이후에는 **센서 다시 연결**을 누릅니다. 명시적으로 **연결 해제**를 누르면 자동 재연결을 중단합니다.
- **수동 재개:** 최신 센서 입력과 유효 보정이 돌아온 뒤 사용자가 직접 재개합니다. 연결 복구만으로 게임이 갑자기 움직이지 않습니다.
- **탭·창 상태:** 탭 숨김, 입력 포커스 상실, 포인터 취소 등에서 입력을 해제합니다. 탭을 다시 열면 일시정지 상태를 확인합니다.
- **느린 화면:** 정상 프레임은 실제 경과 시간으로 계산합니다. 한 프레임의 공백이 250ms를 넘으면 일시정지하고 그 공백을 점수나 유지 시간에 소급해서 더하지 않습니다.

일시정지·숨김·센서 중단 시간은 기록에서 제외합니다. 리듬 게임의 예정된 세트 간 휴식은 본편 진행 시간에 포함합니다.

## 6. 기록 읽기

본편은 입력 출처를 `ble`, `websocket`, `simulation`, `unknown`으로 저장합니다. BLE 본편에는 당시 보정 스냅샷도 함께 저장합니다. 옛 기록의 출처는 `unknown`으로 유지합니다.

홈의 센서 측정 요약과 기록의 실제 센서 필터는 BLE·WebSocket 세션만 집계합니다. XP·레벨·연속 훈련은 시뮬레이션을 포함한 모든 본편 세션을 기준으로 계산합니다. 서버가 없는 경우에도 로컬 기록을 사용할 수 있으며, 서버 전송 대상은 요청 전에 아웃박스에 보존합니다.

서버는 제출 결과로 보상을 재계산하지만, 센서 입력의 진위를 인증하지는 않습니다. 출처 태그는 사용한 입력 경로를 구분하기 위한 값입니다.

## 문제 해결

| 증상 | 확인할 내용 |
|---|---|
| 장치 선택창이 안 열림 | Windows Chrome/Edge인지, HTTPS 또는 localhost인지, 연결 버튼에서 직접 시작했는지 확인 |
| 장치가 목록에 없음 | 전원·BLE 펌웨어·장치 이름을 확인하고 다른 연결 앱을 종료한 뒤 다시 검색 |
| 연결됨인데 시작 불가 | 원시값이 계속 수신되는지와 현재 사용자·기기의 보정 여부 확인 |
| 두 기준 차이가 작음 | FSR 접촉 위치를 고정하고 이완·쥐기 두 단계를 다시 측정 |
| 보정 값이 불안정함 | 같은 자세를 1초 유지하고 센서 배선·접촉·수신 간격 확인 |
| 가변저항을 돌려도 게임이 안 움직임 | 정상 동작. 게임은 GPIO34의 FSR 압력만 사용 |
| 값이 멈추거나 게임이 일시정지됨 | 새 패킷 수신과 연결 상태 확인 → 필요하면 다시 연결 → 준비 후 직접 재개 |
| 예전 Wi-Fi 센서를 사용하려 함 | 센서 입력 확인 안의 기존 Wi-Fi 센서 주소에 `ws://` 또는 `wss://` 주소 입력 |

기존 WebSocket은 `{force, timestamp}`의 논리 압력값 경로입니다. BLE 원시 CSV와 서로 바꿔 보낼 수 없습니다. HTTPS 페이지의 비보안 `ws://` 연결은 브라우저에 의해 제한될 수 있으므로 개발용 localhost 또는 해당 환경의 안전한 연결 구성을 사용합니다.
