## 1. 현재 사용 중인 스택

### 1.1 프론트엔드 (저장소 루트 `*.html`, `shared.js`, `shared.css`)

| 구분 | 기술 | 비고 |
|------|------|------|
| 언어/마크업 | HTML5, Vanilla JavaScript, CSS3 | 프레임워크·빌드 도구 없음 (정적 파일 직접 서빙) |
| 스타일링 | Tailwind CSS (CDN, `forms`·`container-queries` 플러그인) + `shared.css` | 네오 레트로 디자인 시스템은 `shared.css`가 담당 |
| 폰트 | Pretendard (jsDelivr CDN), Space Grotesk / DM Sans (Google Fonts) | 제목: Space Grotesk, 본문: DM Sans/Pretendard |
| 아이콘 | Material Symbols Outlined (Google Fonts) | |
| 게임 렌더링 | Canvas 2D + `requestAnimationFrame` | 미니게임 4종: 풍선·크레인·글라이드·리듬 |
| 데이터 계층 | `DataService` (localStorage ↔ REST `/api/v1` 이중 백엔드) | REST 실패 시 로컬 미러로 폴백 |
| 인증 계층 | `AuthService` (JWT Bearer + refresh 쿠키, 401 → refresh 1회 → 재시도) | `login.html` |
| 센서 통신 | WebSocket (`ws://<esp32-ip>:8080`, JSON `{force, timestamp}`) | `SensorService`, 키보드/마우스 시뮬레이션 모드 내장 |
| 게이미피케이션 | `GamificationEngine` (클라 미러) | 서버(`services/gamification.py`)와 동일 상수·공식, 서버 값이 진실 |

### 1.2 백엔드 (`backend/` — FastAPI 모놀리식)

| 구분 | 기술 | 비고 |
|------|------|------|
| 언어/런타임 | Python 3.11 | `backend/venv` |
| 웹 프레임워크 | FastAPI 0.115 + Uvicorn (ASGI) | 단일 모놀리식, `/api/v1` |
| ORM | SQLAlchemy 2.0 | |
| DB (개발) | SQLite (`regrip_dev.db`) | `DATABASE_URL` 하나로 운영 전환 |
| DB (운영 설계) | PostgreSQL (managed, RDS/Cloud SQL 류) | [01-erd.md](./backend/01-erd.md) DDL 기준 |
| 마이그레이션 | raw SQL (`migrations/*.sql`) | |
| 검증/설정 | Pydantic v2, pydantic-settings (`.env`) | |
| 인증 | PyJWT (HS256) — access 30분 + refresh 쿠키 14일 (`SameSite=Strict`) | 프론트·백엔드 호스트명 일치 필요 |
| 비밀번호 해시 | argon2-cffi | |
| 필드 암호화 | cryptography (AES-GCM) | 전화번호 등 민감정보, [06-security-compliance.md](./backend/06-security-compliance.md) |
| 파일 업로드 | python-multipart | 아바타 → `storage/avatars` (운영은 S3 호환 예정) |
| 타임존 | tzdata (IANA, 기본 `Asia/Seoul`) | 유저별 timezone 설정 |
| 테스트 | pytest + httpx | `backend/tests/` 12개 테스트 파일 |

### 1.3 펌웨어 (`firmware/esp32-grip-sensor/`)

| 구분 | 기술 | 비고 |
|------|------|------|
| MCU | ESP32 (`esp32dev`) | WiFi 내장, 무선 연결 우선 |
| 프레임워크 | Arduino on PlatformIO (`espressif32`) | |
| 통신 | links2004/WebSockets ^2.4 (`WebSocketsServer`, 포트 8080) | 브라우저로 JSON 브로드캐스트 (~20Hz) |
| 센서 | FSR (Force Sensitive Resistor) — ADC 12bit (GPIO34) | 0~4095 → 0~100% 변환 |
| 설정 | `include/config.h` (WiFi 자격증명, `.example`에서 복사) | |

### 1.4 개발 도구

| 구분 | 기술 |
|------|------|
| 통합 실행 | `scripts/dev-start.ps1/.sh` — 프론트 정적 서버(:3000) + FastAPI(:8000) 동시 기동 |
| 정적 서버 | `npx serve` 또는 `python -m http.server` (목업 단독 실행) |
| 펌웨어 빌드 | PlatformIO CLI (`pio run -t upload`, `pio device monitor`) |

## 2. 앞으로 사용할 것 같은 기술 (트리거 기반 로드맵)

> 원칙 ③ "지금 필요한 것만 짓는다" — 아래 기술은 각 트리거 지표 도달 시에만 도입한다.
> 상세 근거는 [05-scaling-roadmap.md](./backend/05-scaling-roadmap.md).

| Stage | 트리거 | 도입 기술 |
|-------|--------|-----------|
| **0 (운영 전환)** | 정식 배포 시점 | managed **PostgreSQL** (RDS/Cloud SQL), **S3 호환 오브젝트 스토리지** + presigned URL (아바타), **단일 컨테이너** 배포 (ECS/Cloud Run 류 managed 컨테이너 서비스) |
| **1** | DAU ≈ 1,000 또는 p95 > 300ms 또는 리더보드 출시 | **Redis** — Sorted Set 리더보드, user_stats 캐시, rate limit 카운터 |
| **2** | B2B 대시보드 집계가 쓰기 경로와 자원 경합 | PostgreSQL **읽기 복제본**, `daily_user_stats` **일별 집계 배치**, **outbox 워커** 분리 (알림/이메일) |
| **3** | B2B 임상 계약 확정 (원시 파형 분석 요구) | **TimescaleDB** 또는 **S3 Parquet 배치** — 원시 시계열 전용 저장·질의 경로 |

### 센서 전송 계층 확장 옵션 (ADR-04-0)

- **BLE** (Web Bluetooth): 공유기 없는 환경 폴백
- **Web Serial API** (USB 유선): 확장 전송 옵션

### B2B 확장 (Stage 3 활성화)

- 병원/치료사 모니터링·처방 기능 — 테이블은 선반영, 기능은 Stage 3에서 활성화 ([07-b2b-extension.md](./backend/07-b2b-extension.md))

## 3. 도입하지 않기로 확정한 기술 (과설계 금지 목록)

| 하지 않을 것 | 한 줄 근거 |
|--------------|-----------|
| 마이크로서비스(MSA) | 수천 명·쓰기 초당 1건 미만 규모에서 운영 복잡도만 증가, 모놀리식으로 충분 |
| Kafka | 부작용 분리는 DB `outbox_events`로 충분 |
| MongoDB | 데이터가 관계형·트랜잭션 중심, 반정형은 PostgreSQL `jsonb`로 커버 |
| GraphQL | 클라이언트가 단일 웹앱, REST로 충분 |
| Kubernetes | 단일~소수 컨테이너 규모, managed 컨테이너 서비스로 충분 |
| 파티셔닝/샤딩 | `sessions` 수천만 행 초과 시에만 월별 파티셔닝 재검토 |

> "지금은 안 한다"이지 "영원히 안 한다"가 아니다. 명시적 트리거 관측 시 재검토한다.
